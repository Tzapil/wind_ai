## 2026-11-28 · T-11 · Сборка береговой линии
Вопрос: Как объединить исходные слои Natural Earth и сохранить повторяемую сборку на Windows и в CI?
Решение: Использовать `mapshaper` как зависимость инструментов для обрезки и упрощения методом Visvalingam; проецировать координаты общей чистой функцией из `core`. Архивы кэшировать вне Git и проверять по SHA-256, а готовый `coast.json` коммитить. Массив `polygons` содержит плоские замкнутые кольца в порядке исходных полигонов: внешнее, затем дыры; при заливке применять правило even-odd.
Почему: Проекция остаётся единой для карты и симуляции; исходные архивы не раздувают репозиторий, а зафиксированные хэши исключают тихую смену версии данных. Формат колец соответствует `number[][]` из ТЗ и подходит для растеризации T-12.

## 2026-11-27 · T-04 · Граница форматирования игрового времени
Вопрос: Как проверить формат даты из `gameTimeOf`, если сама функция появится только в T-21?
Решение: Форматтер клиента принимает объект с полями `year`, `month`, `dayOfMonth`, `hour`, `minute`; тест использует объект этой формы. После T-21 передавать в него результат `gameTimeOf` без дополнительного преобразования.
Почему: T-04 остаётся независимой от реализации календаря ядра и проверяет требуемый русский формат.

## 2026-11-28 · T-10 · Исходные и собранные данные

Вопрос: Как хранить исходные описания портов и ветра до появления координат из mapgen и как проверять их наличие в CI?
Решение: Исходные данные — `data/goods.json`, `ports.json`, `ship.json`, `wind.json`, `balance.json`. Географические дополнения mapgen имеют форму `{ id: { anchorage, exitHeading } }` для портов и `{ id: { x, y } }` для ветровых регионов. `pnpm data:build` проверяет исходные данные схемами zod из core, затем объединяет географию и копирует результат в `packages/client/public/data/`. Пока обоих файлов географии нет, команда предупреждает и копирует исходные данные. После появления `navgrid.bin` их отсутствие становится ошибкой; флаг `--require-generated` позволяет потребовать их раньше. Сборка клиента запускает data:build, поэтому проверка входит в CI.
Почему: Исходные координаты остаются неизменными, а generated файлы становятся обязательны вместе с картой в T-12. zod в core прямо предусмотрен T-10; для запуска TypeScript-схем из Node используется закреплённый в CI Node 24.

## 2026-11-27 · T-03 · Временная работа без GitHub Actions
Вопрос: GitHub Actions не запускает задания из-за блокировки аккаунта по вопросу оплаты; как продолжать работу над проектом?
Решение: По прямому указанию автора временно не ждать CI. Выполнять локальные проверки из `AGENTS.md` перед слиянием PR. Когда Actions станет доступен, проверить workflow и скачанный артефакт T-03.
Почему: Локальные lint, typecheck, test, build и production preview уже прошли; блокировка находится на стороне аккаунта GitHub.

## 2026-11-27 · T-02 · Границы импортов в ESLint
Вопрос: Как проверять правила слоёв до появления остальных модулей без дополнительной зависимости?
Решение: Использовать встроенные `no-restricted-imports`, `no-restricted-globals`, `no-restricted-properties` и `no-restricted-syntax` с отдельными правилами для `core`, `worker`, `render` и `ui`.
Почему: ESLint уже установлен; ограничения проверяются на будущих файлах соответствующих каталогов, а намеренные нарушения каждого слоя дают явные сообщения.

## 2026-11-27 · T-01 · Слияние первого PR до появления CI
Вопрос: В T-01 требуется зелёный CI, но workflow появляется только в T-03; у PR #1 нет проверок.
Решение: По прямому выбору автора слить PR #1 после локальных lint, typecheck, test, build и e2e. Добавить CI в T-03.
Почему: Это сохраняет границы задач и позволяет начать T-02; отсутствие CI для первого PR зафиксировано явно.

## 2026-11-27 · T-01 · Версия TypeScript и проверка в браузере
Вопрос: Стабильный TypeScript 7 пока не поддерживается актуальным `typescript-eslint`; как сохранить проходящий линтер и браузерную проверку на Windows?
Решение: Закрепить TypeScript 6.0.3. Smoke-тест Playwright на Windows запускается через установленный Edge, на других системах — через Chromium Playwright.
Почему: TypeScript 6 входит в диапазон поддержки линтера, а на машине автора Edge доступен без глобальной установки браузера.

## 2026-11-27 · T-01 · Локальная основа репозитория
Вопрос: Подготовленные документы лежали в корне, хотя правила проекта ожидают их в `docs/design/`; Git в папке не был инициализирован.
Решение: Создать локальный `main` с исходными файлами, затем ветку `t-01-repository-monorepo`; перенести документы в `docs/design/` без изменения содержания. Для строки LICENSE использовать подтверждённый автором ник `tzapil`.
Почему: Сохраняется исходная заготовка и выполняется согласованная структура проекта. Личный адрес почты не попадает в публичную историю.
